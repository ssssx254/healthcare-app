# BRD — Бизнесийн шаардлагын баримт бичиг

**Төсөл:** Tusul2 (ServiceHub Healthcare)  
**Хувилбар:** 1.0  
**Огноо:** 2026 оны 5 сар  
**Хэл:** Монгол  
**Зорилтот хэрэглэгч:** Бизнес эзэн, менежмент, хөрөнгө оруулагч, төслийн баг

---

## 1. Дүгнэлт (Executive Summary)

Tusul2 нь **Монголын эрүүл мэндийн үйлчилгээг нэгтгэсэн дижитал платформ** юм. Үйлчлүүлэгч (өвчтөн) эмнэлэг, эмчийг хайж, **үнэгүй онлайн зөвлөгөө** эсвэл **төлбөртэй цаг захиалга** авч, төлбөр төлж, чатаар холбогдоно. Үйлчилгээ үзүүлэгч (эмнэлэг, клиник) платформд бүртгүүлж, эмч, үйлчилгээ, хуваарь, захиалгаа удирдана. Системийн админ платформыг хянаж, бүртгэл баталгаажуулна.

**Бизнесийн үндсэн санал:** нэг апп-аар зөвлөгөө + захиалга + төлбөр + харилцааг төвлөрүүлж, эмнэлэг болон өвчтөний цагийг хэмнэх, орлогыг ил тод болгох.

## 2. Бизнесийн контекст

### 2.1 Асуудал

| Асуудал | Одоогийн байдал | Платформын шийдэл |
|--------|----------------|-------------------|
| Эмч, эмнэлэг олоход хүнд | Утас, Facebook, санал зөвлөмж | Нэгтгэсэн хайлт, ангилал, жагсаалт |
| Цаг захиалга тодорхой биш | Давхардал, мартагдах | Онлайн хуваарь, баталгаажсан цаг |
| Төлбөрийн процесс төөрөгдөлтэй | Бэлэн, данс шилжүүлэг | Цахим данс, QPay, карт (төлөвлөгөө) |
| Эхний зөвлөгөө үнэтэй | Хандалт бага | Үнэгүй онлайн зөвлөгөөний цаг |
| Эмнэлгийн мэдээлэл тархмал | Лого, танилцуулга байхгүй | Эмнэлгийн профайл, лого, үнэлгээ |

### 2.2 Зорилтот зах зээл

- **Үйлчлүүлэгч:** Улаанбаатар болон хот, хөдөөгийн иргэд; интернэт ашигладаг; эмч, эмнэлэгт хялбар хандахыг хүсдэг.
- **Үйлчилгээ үзүүлэгч:** Хувийн эмнэлэг, клиник, зөвлөгөөний төв; онлайн захиалга, маркетинг, чат хэрэгцээтэй.
- **Платформ оператор:** Системийн админ — чанар, бүртгэл, төлбөрийн хяналт.

## 5. Бизнесийн хүрээ

### 5.1 Хамрах хүрээнд (In Scope)

- Хэрэглэгчийн бүртгэл, нэвтрэлт (үйлчлүүлэгч, үзүүлэгч, админ)
- Үзүүлэгчийн бүртгэл, админы баталгаажуулалт
- Эмнэлэг, эмч, үйлчилгээ, цагийн хуваарийн удирдлага
- Үнэгүй онлайн зөвлөгөө + төлбөртэй цаг захиалга
- Төлбөр: цахим данс, QPay; карт (хөгжүүлэлтэд)
- Чат (үйлчлүүлэгч ↔ эмнэлгийн тал)
- Эмчийн үнэлгээ, сэтгэгдэл
- Мэдэгдэл (push placeholder)
- Шинжилгээний хариу (lab tests) — provider өгөх, customer харах
- Эрүүл мэндийн анкет (захиалгын өмнө)
- Вэб + мобайл (Expo) — нэг кодын сан

### 5.2 Хамрах хүрээнээс гадуур (Out of Scope) — одоогийн хувилбарт

- ЭМД / даатгалын бодит API холболт (зөвхөн UI placeholder)
- Бодит видео дуудлага (Meet link placeholder)
- Эмийн жор, жорын сан
- Олон улсын хэл (зөвхөн Монгол UI)
- Эмнэлгийн дотоод ERP, нягтлан бодох бүрэн систем

## 6. Үйлчилгээний загвар (Business Model)

### 6.1 Үйлчилгээний төрлүүд

| Төрөл | Тайлбар | Үнэ | Бизнесийн зорилго |
|-------|---------|-----|-------------------|
| **Үнэгүй онлайн зөвлөгөө** | Тодорхой цагт эхний зөвлөгөө, чат/Meet | 0 ₮ | Хэрэглэгч татах, итгэл үүсгэх |
| **Төлбөртэй үзлэг** | Эмчийн албан ёсны цаг | Үйлчилгээнээс хамаарна | Үндсэн орлого |
| **Онлайн зөвлөгөө (төлбөрт)** | Ирээдүйд төлбөртэй онлайн | Тохируулна | Өргөтгөл |

### 6.2 Орлогын урсгал (тохиолдол)

1. Үйлчлүүлэгч төлбөртэй цаг захиална → төлбөр төлнө (данс / QPay).
2. Платформ шимтгэл авч болох (ирээдүй — BRD-т тодорхойлоогүй, хувь хэмжээ бизнесийн шийдвэр).
3. Үзүүлэгчид үлдэгдэл шилжүүлнэ (wallet / дансны логик хөгжүүлэгдэж байна).

## 7. Гол бизнесийн процессууд

### 7.1 Үйлчлүүлэгч — төлбөртэй захиалга

```
Нэвтрэх → Эмнэлэг/эмч сонгох → Үйлчилгээ + цаг сонгох → Анкет бөглөх
→ Төлбөрийн арга сонгох → Төлбөр → Баталгаажсан захиалга → Чат / Meet (placeholder)
→ Үзлэг дууссаны дараа эмчид үнэлгээ өгөх
```

### 7.2 Үйлчлүүлэгч — үнэгүй зөвлөгөө

```
Нүүр → Үнэгүй зөвлөгөө → Эмч + өдөр/цаг сонгох → Захиалга батлах
→ Чат нээх → (Meet холбоос ирээдүйд)
```

### 7.3 Үйлчилгээ үзүүлэгч — платформд нэгдэх

```
Бүртгүүлэх (provider) → Онбординг маягт + лого → Админ баталгаажуулна
→ Эмнэлэг үүсгэх → Эмч нэмэх → Үйлчилгээ + үнэгүй цаг төрөл тохируулах
→ Хуваарь нэмэх → Захиалга хүлээн авах / баталгаажуулах
```

### 7.4 Системийн админ

```
Нэвтрэх → Хүлээгдэж буй үзүүлэгчийг шалгах → Зөвшөөрөх / татгалзах
→ Эмнэлэг, хэрэглэгч, төлбөрийн хяналт → Онцлох эмч/контент удирдах
```
